概述

本平台是面向开发者与 AI 应用的大模型 API 聚合中转服务：你只需要一个 API Key、一个接入地址，即可调用平台聚合的全部主流大模型，无需分别到各家厂商注册、绑卡、维护多套密钥，也不必为每家模型单独写一套适配代码。

整套服务完全兼容 OpenAI 协议 —— 已有项目通常只改一行 base_url 就能跑起来；计费采用按次扣积分，与 token 数量无关，长文与长输出不加价。

接入三要素

无论用 SDK、命令行还是第三方客户端，需要填的永远是这三样：

要填什么填什么值
接入地址 https://v1.pvaki.com/v1
部分客户端会自己拼接路径，那种情况填不带 /v1 的 https://v1.pvaki.com（见「客户端接入」）
备用地址 https://v1.wifdo.com/v1
上面的地址连接超时 / 连不上，或你的电脑本身走海外网络时，换这个即可，Key 与功能完全相同（另一条线路、不同服务器）
API Key在 「我的 Key」 自助签发的 sk- 开头密钥，可签多把、分别限额
模型名在 模型广场 一键复制，或调 GET /models 拉取当前 Key 可用清单
接入失败先看这里

最常见的报错是 404，几乎都是接入地址的 /v1 多填或少填导致的。其次是 401，通常是 Key 复制时带了空格或已被删除。各类报错的短码对照见「错误码」一节。

核心能力

  • OpenAI 协议完全兼容 —— 任何支持 OpenAI 接口的 SDK、客户端或 Agent 框架，把 base_url 换成平台地址即可直接使用，请求与响应结构保持原样。
  • 一个端点调全部模型 —— 无论模型上游属于哪种协议，统一走 /chat/completions，平台在服务端自动完成协议适配（含上游为 Anthropic 协议的模型），不必按模型区分端点。
  • 三套协议同时提供 —— 除 OpenAI /chat/completions 外，还兼容 Anthropic Messages（/messages，供 Claude Code 等）与 OpenAI Responses（/responses，供 Codex CLI、Agents SDK 等），三者共用同一把 Key、同一套计费。
  • 完整能力开箱即用 —— 流式输出、工具调用（Function Calling）、深度思考全模型支持；视觉识图取决于具体模型（资料卡有标注），支持的模型识图不额外加价（详见「能力说明」）。
  • 参数与线路兜底 —— 个别模型不支持的参数会自动剥离或降级，上游偶发不可用时自动切备用线路，尽量不让请求因这些差异而失败。

为什么用聚合中转

  • 省掉多平台开户 —— 不必逐家注册、绑定境外支付、分别维护密钥与配额，一个账户覆盖全部上架模型。
  • 成本可精确预估 —— 按次计费，一次调用扣一次固定单价，不必按输入/输出 token 分别估算，做预算和对账都简单。
  • 换模型不改代码 —— 切换模型只需改请求里的 model 字段，横向对比不同厂商的效果几乎零成本。
  • 额度可控 —— 每把 Key 可单独设总额度与 5 小时 / 日 / 月窗口限额，给不同项目或成员分发时互不影响。

计费口径速览

  • 只有成功的调用（HTTP 2xx）才计费，失败请求不扣积分。
  • 每次扣费 = 该模型的按次单价，与 token 数量、是否流式、是否带图都无关。
  • 单价以模型广场展示为准；已签发的 Key 按签发时价格锁定，可在「我的 Key」点该密钥的「价格」查看实际单价。
  • 额度用尽或 Key 过期后请求会被拒绝，续充或重新签发即可恢复。完整单价表与口径见「定价与用量」。

接下来

  • 第一次使用 —— 从「快速开始」照着三步走，五分钟内跑通首个请求。
  • 从其他平台迁移 —— 看「迁移指南」，多数情况只需改接入地址与 Key。
  • 用现成工具 —— 看「客户端接入」，Cursor、Claude Code、Cherry Studio 等都有独立配置说明。
  • 挑模型 —— 看「模型列表」，展开厂商即可查看每个模型的定位、能力与单价。

快速开始

从零到跑通第一个请求只有三步。已经有 OpenAI 兼容项目的话，直接看「迁移指南」会更快。

三步上手

  1. 充值积分：前往 充值积分 页选择面额，支付后自动到账。
  2. 签发 API Key：前往 我的 Key 页签发密钥，设定总额度（1 积分额度 = 1 积分）与有效期；签发后立即复制保存你的 sk- 开头密钥。
  3. 发起第一个请求：把下面命令里的 Key 与模型名换成你自己的（模型名可在 模型广场 一键复制）。
cURL 
curl https://v1.pvaki.com/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-你的Key" \
  -d '{
    "model": "Kimi-K2.6",
    "messages": [
      {"role": "user", "content": "你好，用一句话介绍你自己"}
    ]
  }'

请求成功即返回标准 OpenAI 格式 JSON，并按该模型单价从 Key 额度中扣除相应积分。

换用 Responses 协议

如果你用的是 Codex CLI、OpenAI Agents SDK，或新版 OpenAI SDK 的 client.responses.create()，可以直接打 /responses —— 同一把 Key、同一套按次计费，只是请求与响应换成 Responses 格式：

cURL 
curl https://v1.pvaki.com/v1/responses \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-你的Key" \
  -d '{
    "model": "Kimi-K2.6",
    "instructions": "你是一个简洁的中文助手。",
    "input": "用一句话介绍你自己",
    "max_output_tokens": 300
  }'

对话内容放 input（字符串或消息数组均可），系统提示放 instructions，长度上限用 max_output_tokens。响应正文在 output[0].content[0].text，多数 SDK 也提供 output_text 便利字段：

JSON 
{
  "id": "resp_xxxxxxxx",
  "object": "response",
  "status": "completed",
  "model": "Kimi-K2.6",
  "output": [
    {
      "type": "message",
      "role": "assistant",
      "content": [
        { "type": "output_text", "text": "我是一个可以帮你写代码和答疑的 AI 助手。" }
      ]
    }
  ],
  "output_text": "我是一个可以帮你写代码和答疑的 AI 助手。",
  "usage": { "input_tokens": 24, "output_tokens": 18, "total_tokens": 42 }
}

加 "stream": true 即为标准 Responses 事件流（response.output_text.delta 等）；工具调用（tools / function_call）同样支持。不支持 previous_response_id、store 这类有状态会话 —— 平台为无状态中转，每次请把完整对话放进 input。

没有列出的端点就是不支持

平台专注大模型对话，不提供向量嵌入（/embeddings）、图像生成（/images/generations）、语音转写与合成（/audio/*）、重排序（/rerank）、内容审核（/moderations）以及旧版补全（/completions）等端点，调用它们会返回 404。如果你的项目依赖这些能力，请另行接入对应服务。

你不需要关心某个模型上游走什么协议 —— 统一用 /chat/completions 即可，平台在服务端自动完成协议转换与参数适配。/messages 与 /chat/completions 共用同一把 Key、同一套计费与并发限制，换端点不会绕过任何限制。

迁移指南

如果你已有基于 OpenAI 官方接口（或任意 OpenAI 兼容服务）的代码，迁移只需要改两处 —— 接入地址与密钥，其余代码零改动。

Python（openai 官方 SDK）

Python 
from openai import OpenAI

client = OpenAI(
    base_url="https://v1.pvaki.com/v1",
    api_key="sk-你的Key",
)

resp = client.chat.completions.create(
    model="Kimi-K2.6",
    messages=[
        {"role": "user", "content": "用 Python 写一个快速排序"},
    ],
)
print(resp.choices[0].message.content)

Node / TypeScript（openai 官方 SDK）

import OpenAI from "openai";

const client = new OpenAI({
  apiKey: "sk-你的Key",

const r = await client.chat.completions.create({

从 Anthropic / Claude 生态迁移

用 Anthropic 官方 SDK 或 Claude 系客户端（含 Claude Code）的应用，把接入地址指向平台的 /messages 端点即可（见「Claude 格式」）。用 Codex CLI 或 OpenAI Agents SDK 的，指向 /responses（见「快速开始」）。当然，统一用 /chat/completions 也能调用全部模型。

迁移前请注意这些差异

你原来可能依赖在本平台
模型名（如 gpt-4o、claude-3-5-sonnet）需要替换成平台的模型名，见模型广场或 GET /models
按 token 计费改为按次计费：一次成功调用扣固定单价，与长度无关
n 返回多个候选不生效，一次只返回一条回答
向量嵌入 / 图像生成 / 语音不提供，需另接服务（见「快速开始 → 可用端点」）
有状态会话（previous_response_id）不支持，每次请带完整对话
所有模型都能识图取决于模型，以资料卡标注为准，平台不做识图兜底
官方的组织/项目管理、微调、Batch API不提供

迁移后建议先跑一遍「快速开始」里的最小请求确认连通，再逐步替换模型名。遇到 404 先检查接入地址的 /v1，遇到 401 先确认 Key 复制完整。

对话接口 Chat Completions

POST https://v1.pvaki.com/v1/chat/completions

主要请求参数

参数类型必填说明
modelstring是模型名（从 模型广场 复制，或 GET /models 获取）
messagesarray是对话消息数组，元素含 role（system / user / assistant / tool）与 content
streamboolean否true 开启流式输出（SSE），默认 false
max_tokensnumber否最大输出长度；缺省由模型自身决定。思考型模型建议给足（≥1000），否则思考未结束就被截断，可能只拿到空正文
temperaturenumber否采样温度；支持范围随模型而定，超出时平台自动收敛
top_pnumber否核采样；与 temperature 建议只调其一
stopstring / array否停止序列，命中即结束输出
tools / tool_choicearray / string否工具调用（Function Calling），OpenAI 格式，见「能力说明」
response_formatobject否{"type":"json_object"} 约束模型输出合法 JSON；个别模型不支持时平台自动剥离该参数
presence_penalty
frequency_penalty		number否重复惩罚，按原样透传给模型
seednumber否随机种子，按原样透传；不保证可复现（取决于模型）
stream_optionsobject否如 {"include_usage":true}，流式结束前附带 token 统计

其余 OpenAI 协议参数按原样透传，未知参数会被忽略而不会报错；个别模型不支持的参数或取值，平台自动剥离或降级，尽量保证请求不因参数差异而失败。

一次请求只返回一个回答

n 参数不生效：即使传 "n": 2，响应里 choices 也只有一条（不会报错，也不会多扣费）。需要多个候选请自行发多次请求 —— 那会按次数分别计费。

响应字段

字段说明

平台按次计费，与 usage 里的 token 数量无关 —— 该字段只用于你自己估算上下文长度。

流式输出

请求体加 "stream": true 即开启流式，响应为标准 SSE（text/event-stream）：每行 data: 携带一个增量 chunk，正文增量在 choices[0].delta.content，以 data: [DONE] 结束。

cURL 
curl https://v1.pvaki.com/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-你的Key" \
  -d '{
    "model": "Kimi-K2.6",
    "stream": true,
    "messages": [
      {"role": "user", "content": "写一首关于星空的短诗"}
    ]
  }'

响应片段

SSE 
data: {"id":"chatcmpl-xxx","object":"chat.completion.chunk","choices":[{"index":0,"delta":{"role":"assistant","content":"夜"}}]}

data: {"id":"chatcmpl-xxx","object":"chat.completion.chunk","choices":[{"index":0,"delta":{"content":"空"}}]}

data: {"id":"chatcmpl-xxx","object":"chat.completion.chunk","choices":[{"index":0,"delta":{},"finish_reason":"stop"}]}

data: [DONE]
Python（流式） 
stream = client.chat.completions.create(
    model="Kimi-K2.6",
    messages=[{"role": "user", "content": "讲一个冷笑话"}],
    stream=True,
)
for chunk in stream:
    delta = chunk.choices[0].delta.content or ""
    print(delta, end="", flush=True)

结束原因与用量

  • 最后一个含内容的 chunk 会带 finish_reason：stop 正常结束、length 触达 max_tokens 被截断、tool_calls 等待你回填工具结果。
  • 需要 token 统计时传 "stream_options": {"include_usage": true}，平台会在流末附带 usage（仅供参考，不参与计费）。
  • 流以 data: [DONE] 结束。请按 SSE 逐行解析，不要等整个响应体读完再处理 —— 否则失去流式意义。

常见问题

  • 看起来不流式、内容一次性全出：多半是中间层缓冲。检查自己的反向代理 / 网关是否开了响应缓冲（nginx 需 proxy_buffering off），以及 SDK 是否真的用了流式接口。
  • 思考型模型迟迟不出字：模型在推理阶段还没产出正文，平台会先发保活字节维持连接。请把 max_tokens 给足（≥1000），否则可能思考没结束就被截断、正文为空。
  • 客户端中途断开：请求会随之终止，不会继续消耗上游。

流式与非流式同价（同一模型每次调用扣费一致），不会因为分了很多 chunk 而多扣。

与 OpenAI 格式的字段差异

常见问题

运行命令后，Claude Code 还是连到之前用的服务

命令写的是个人配置，会覆盖之前配过的其它服务（包括系统环境变量里留下的旧地址和旧 Key）。请确认是新开的终端窗口，并在 Claude Code 里执行 /status 看地址；若命令窗口提示「检测到公司统一下发的 Claude Code 配置」，那份配置优先级更高，需要电脑管理员处理。

想恢复成运行命令之前的配置

命令运行时会把原文件备份成 settings.json.bak-时间（在 ~/.claude 目录里），把备份改回 settings.json 即可。

报「该模型暂不支持 [E2001]」

最常见的原因：模型映射没配全。Claude Code 内部会按 opus / sonnet / haiku 三档分别请求模型（子任务、文件搜索走 haiku），只配 ANTHROPIC_MODEL 时，其余档位仍会用 claude-sonnet-… 这类官方模型名请求本平台，必然报此错。用「配置到客户端」的命令会一次写全；手动配置时请把上方示例里的四个模型字段全部填上。

启动后提示 Unable to connect to Anthropic services

说明请求仍打向 Anthropic 官方。依次排查：① ~/.claude.json 的 hasCompletedOnboarding 是否为 true；② settings.json 路径与 JSON 格式是否正确；③ 是否新开了终端窗口；④ 执行 /status 看 BASE_URL 指向哪里。

之前设过官方的 ANTHROPIC_API_KEY，现在报 401

两个凭证会冲突。先 unset ANTHROPIC_API_KEY（Windows 用 Remove-Item Env:ANTHROPIC_API_KEY）再启动。

报 Connection refused / Request timeout，或第三方切换工具「连接测试」失败

分三步：① 连接被拒（refused）多半是本机残留了代理变量 —— 执行 set | findstr /I proxy（macOS/Linux 用 env | grep -i proxy），看到 HTTP_PROXY / HTTPS_PROXY 指向 127.0.0.1 就清掉，或把对应代理软件打开；用本平台不需要开代理。② 连接超时：在终端执行 curl https://v1.pvaki.com/v1/models，超时说明你的网络到主线路不通（本机走海外网络时常见），把 ANTHROPIC_BASE_URL 改成备用地址 https://v1.wifdo.com 即可，Key 与功能完全一致。③ 第三方工具的「连接测试」超时不代表不可用 —— 它们的超时通常只有十几秒，而深度思考类模型（名字带 Thinking-Max 等）响应本来就要十几到几十秒；把测试模型换成快速模型（如 Gemini-3.5-Flash），或直接在 Claude Code 里使用（它自己的超时是 10 分钟）。

想用别的模型 / 想给子任务用更便宜的模型

把 ANTHROPIC_MODEL 与三档默认模型改成模型广场里的其它名称即可。CLAUDE_CODE_SUBAGENT_MODEL 单独控制子任务用的模型，设成便宜的快速模型可以明显省积分。

抓网页（WebFetch）报 Unable to verify if domain is safe，网页一个都打不开

Claude Code 抓网页前会先连 Anthropic 官方检查这个网址，国内连不上就整个失败，和本平台无关。在 ~/.claude/settings.json 最外层加一行 "skipWebFetchPreflight": true（与 env 同级，见上方示例），重开 Claude Code 即可。用「配置到客户端」的命令会自动写上，以前运行过的重新运行一次就行。要写在用户目录这份，写在项目目录的 .claude/settings.json 里有时不生效。

前置条件

  • 按 OpenCode 官网说明安装命令行工具。

配置步骤

  1. 编辑 ~/.config/opencode/opencode.json（Windows：%USERPROFILE%\.config\opencode\opencode.json），不存在就新建。
  2. 按下方示例加入 provider，models 里逐个登记你要用的模型（没登记的不会出现在选择列表）。每个模型都要各自写一遍 modalities，漏写的那个模型发不出图片。
  3. 保存后重启 opencode，用 /models 命令选择模型。

opencode.json

JSON 
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "yt": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "宇天科技",
      "options": {
        "baseURL": "https://v1.pvaki.com/v1",
        "apiKey": "sk-你的密钥"
      },
      "models": {
        "GPT-5.6-Sol-Max-Fast": {
          "name": "GPT-5.6-Sol-Max-Fast",
          "modalities": { "input": ["text", "image"], "output": ["text"] },
          "tool_call": true
        },
        "Gemini-3.5-Flash": {
          "name": "Gemini-3.5-Flash",
          "modalities": { "input": ["text", "image"], "output": ["text"] },
          "tool_call": true
        }
      }
    }
  }
}

验证是否接入成功

重启后执行 /models，能看到「宇天科技」下的模型即配置生效；选中后随便问一句验证能否正常回复。

常见问题

发了图片，模型却毫无反应或说看不到

两个原因，请依次排查：
① OpenCode 没把图发出来。自定义 provider 没有内置模型元数据，每个模型都必须各自声明 "modalities": { "input": ["text", "image"] }（见上方示例）——只在第一个模型上写、其余漏写是最常见的情况。另外配置里还有个 attachment 字段，它与图片输入无关，只配它没有任何作用。
② 该模型本身不支持识图。请在模型广场选带「识图」标签的模型。给不支持识图的模型发图，会直接返回 E2004 明确报错，该次请求不计费。

模型列表里看不到我要的模型

models 里没登记的模型不会出现。补上一条即可，名称需与模型广场完全一致。

补充说明

  • 模型名区分大小写，建议直接从模型广场复制。

定价与用量

平台采用按次计费：每次成功调用，按所用模型的按次单价（积分/次）从这把 Key 的额度里扣除，与输入输出 token 数量无关。长文、长输出、带图都不加价，成本可以按「预计调用次数 × 单价」精确预估。

积分与计费单位

  • 积分是平台内唯一的计费单位，充值到账后进入账户余额，签发或续充 Key 时从余额划转成 Key 额度。
  • 基准是 1 元 = 1 积分；大额面额常有活动加赠，实际到账积分以 充值积分 页面实时展示为准。
  • 余额分实充与赠送两部分：两者都能用于签发和续充，但赠送积分不可退款，也不计入累计实付金额。
  • 签发与续充按 1:1 划转 —— 签 1000 积分额度就扣 1000 积分，不额外收手续费。

一次调用扣多少

  • 只有成功的调用计费：鉴权失败、参数错误、额度不足、上游异常等失败请求一律不扣费。
  • 流式与非流式同价：加不加 stream: true 扣费完全一致。
  • 识图不加价：带图请求与纯文本请求同价，按次扣一次。
  • 工具调用按轮次计费：模型发起 tool_calls 后你回填结果再续写，那是新的一次请求，会再扣一次。
  • 已签发的 Key 按签发时价格锁定：后续平台调价不影响存量 Key。想查某把 Key 的真实单价，到 「我的 Key」 点该密钥的「价格」。

邀请返利

邀请好友注册并充值，你可以获得持续的积分返佣，好友也能拿到入门礼包与首充奖励。本节说明规则与口径；具体门槛、返佣比例与你当前的进度，以 「邀请有奖」 页面实时展示为准。

怎么运作

  1. 解锁邀请：累计实付充值达到门槛后解锁邀请功能，未达标时可在邀请页查看进度。
  2. 生成邀请码：一个邀请码对应一位好友，可以给它附带一份入门礼包额度（也可以不带）。
  3. 好友用码注册：好友在注册页填入邀请码即建立邀请关系，礼包积分立即到账给好友。
  4. 持续获得返佣：此后好友每一次在线充值，你都按当前档位比例获得积分返佣，不只第一笔。

三类奖励

  • 入门礼包 —— 给好友的，额度由你在生成邀请码时自行分配，从你的可分发邀请额度里扣。
  • 好友首充奖 —— 好友首次充值任意金额，双方都有；邀请人一侧的奖励随已成功邀请的人数递减。
  • 持续返佣 —— 好友每次在线充值按比例返你积分，比例由你的累计实付档位决定。

档位与比例

门槛按累计实付金额（元）分档，档位越高返佣比例越高，每跨一档还会额外赠送一批可分发的邀请额度。

档位不锁定

返佣比例按你当前档位实时计算，不在建立邀请关系时锁定 —— 升档之后，之前邀请的好友再充值也按新的更高比例返佣。

累计实付按实际支付金额累计，不按到账积分。举例：某面额有活动加赠，付 600 元到账 700 积分，计入档位进度的是你真实支付的 600 元，不是 700。

奖励到账与使用

  • 奖励在好友充值成功后自动结算，无需申请；可在 积分账单 看到「邀请返佣」「好友首充奖励」「邀请礼包」等流水。
  • 奖励全部计入赠送积分：可以正常用于签发和续充 Key。
  • 赠送积分不可退款，也不计入你自己的累计实付金额（即不能靠奖励推高自己的返佣档位）。

注意事项

  • 一码一人一次：邀请码被使用后即失效；尚未被使用的邀请码可以作废，额度会全额退回。
  • 不能自己邀请自己，同一账号也不能重复绑定邀请关系。
  • 只有在线自助充值触发返佣；客服人工入账不参与返佣结算。
  • 如发现刷单、批量注册等异常行为，平台有权撤销相关奖励并停用邀请功能。

常见问题

支持哪些模型？

以 模型广场 实时展示为准，也可用 GET /models 探测当前 Key 可调用的清单。模型持续上新。

和 OpenAI 官方 SDK 完全兼容吗？

是。只需把 base_url 改为 https://v1.pvaki.com/v1、api_key 换成平台签发的 Key，其余代码不用动。

长对话、长输出会更贵吗？

不会。平台按次计费，每次调用扣「该模型单价」对应的积分，与 token 数量无关（超长上下文以模型自身上限为准）。

请求失败会扣积分吗？

不会。仅成功返回的调用计费；鉴权失败、参数错误、上游异常等均不扣费。

调用思考 / 推理模型返回空内容？

思考类模型会先消耗额度进行推理再输出正文。若 max_tokens 设得过小，额度可能在推理阶段就被耗尽，导致正文为空且 finish_reason=length。建议调用思考模型时把 max_tokens 设为 1000 以上或不传（由模型自行决定）。

为什么模型说「没有看到图片」？

你选的模型本身不支持识图。平台不做识图兜底（不会背后把你换到别的模型），给不支持识图的模型发图时请求仍会成功并计费，但图片会被替换成文字占位、不会送达模型。请在「模型列表」里挑标注视觉模型的那些，详见「能力说明 → 视觉识图」。

报 404 Not Found 怎么办？

九成是接入地址的 /v1 多填或少填。用 SDK（openai-python / node）时填 https://v1.pvaki.com/v1；部分会自己拼路径的客户端要填不带 /v1 的 https://v1.pvaki.com，具体见「客户端接入」里对应工具的说明。另一种可能是调用了平台不提供的端点（如 /embeddings），见「快速开始 → 可用端点」。

报 401 / 密钥无效怎么办？

依次检查：Key 是否复制完整（含 sk- 前缀、首尾无空格或换行）；是否在「我的 Key」里被停用或已过期；是否误用了账号密码而非 Key。报错末尾的短码能进一步定位 —— [E1002] 无效、[E1003] 已停用、[E1004] 已过期。

报 429 是被限速了吗？

不是全局限速，而是这把 Key 的额度或窗口限额到了。看短码区分：[E1005] 总额度用尽（去「我的 Key」续充）、[E1006] 今日、[E1007] 当前 5 小时、[E1008] 本月窗口用尽（等窗口滚动重置或调高上限）、[E4002] 平台侧繁忙（稍后重试即可）。

有速率限制吗？并发能开多大？

平台不设一刀切的全局速率墙。你可以在签发 Key 时配置 5 小时 / 单日 / 每月窗口限额，用于控制预算与防止密钥被盗刷。单把 Key 另有并发上限（触发时返回 [E4001]），如需调高请联系在线客服。

怎么在程序里查这把 Key 还剩多少？

调 GET https://v1.pvaki.com/v1/usage（免费、不扣额度），返回该 Key 的总额度、已用量、剩余与各窗口用量，适合做低额度告警。Cherry Studio、NextChat 等客户端的「查询余额」按钮也已兼容。详见「快速开始 → 查询本 Key 余量」。

一把 Key 能分给多个项目或同事用吗？

可以，而且建议按用途分开签发：每把 Key 可单独设总额度、窗口限额、有效期与模型权限，互不影响，出问题也能单独停用。注意 GET /usage 只返回该 Key 自己的额度，不会暴露你的账户总余额。

模型清单会变吗？需要硬编码模型名吗？

会变（持续上新，个别模型也可能下架或临时不可用）。建议用 GET /models 动态获取，或在配置里留出可改的位置，不要把模型名写死在代码深处。已签发的 Key 单价按签发时锁定，平台调价不影响存量 Key。

为什么传了 n 还是只返回一个回答？

n 参数在本平台不生效（不报错、也不多扣费），一次请求固定返回一条回答。需要多个候选请自行发多次请求，那会按次数分别计费。

我的请求数据安全吗？

请求内容仅用于完成本次调用与结算所必需的转发和记录，不用于模型训练。详见页脚 隐私政策。

usage 里的 token 数会影响费用吗？

不会。usage 只是给你估算上下文长度用的参考值，计费完全按次。思考型模型的推理消耗可在 usage.completion_tokens_details.reasoning_tokens 看到，同样不影响扣费。
